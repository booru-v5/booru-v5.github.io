# BOORU V5

**https://booru-v5.github.io/**

NovelAI V5로 그림을 만들 때 쓰는 **단부루(Danbooru) 태그 45,420개**를 한글명·게시물 수·관련 태그와 함께 찾아보는 웹 페이지입니다. 설치할 것 없이 브라우저에서 바로 열립니다.

## 무엇을 할 수 있나요

- **검색** — 영어(`long hair`), 한글(`긴 머리`), 초성(`ㄱㅁ`) 모두 됩니다. 위키 설명 본문까지 항상 함께 검색합니다.
- **복사** — 태그를 누르면 NovelAI 입력 형태(밑줄 → 공백)로 클립보드에 복사됩니다. 관련 태그 패널에서는 보이는 목록을 한 번에 복사할 수도 있습니다.
- **분류 필터** — 대분류(일반 / 캐릭터 / 작품 / 작가 / 메타 / NAI전용) → 중분류(14개 그룹) → 소분류(82개) 드롭다운 3단으로 좁혀 갑니다.
- **관련 태그** — 일반 태그를 펼치면 함께 쓰이는 태그가 **태그당 최대 200개**까지 **분류별로 묶여** 나옵니다. 목록은 패널 안에서 따로 스크롤되므로 행이 길어지지 않습니다. 연관도(코사인)순 ↔ 빈도순, 분류별 ↔ 전체 보기 전환을 지원하고, `흔한 태그 숨기기`(`1girl` `solo` 처럼 어디에나 붙는 태그를 빼기)는 **기본 꺼짐**입니다.
- **이동** — 관련 태그 옆 `이동`을 누르면 그 태그의 본문 항목으로 바로 건너뜁니다. 지금 걸린 검색·분류 때문에 목록에 없으면 조건을 풀어서라도 찾아갑니다.
- **성인 태그 토글** — 우측 상단에 있습니다. **기본은 꺼짐**이고, 켤 때만 연령 확인 모달이 뜹니다. 꺼져 있으면 성인 관련 태그가 목록·검색·관련 태그 어디에도 나오지 않고, 표시되는 개수도 숨긴 기준으로 셉니다.
- **설명 전문** — 각 태그마다 단부루 위키 기반 설명과 키워드를 목록에서 바로 읽을 수 있습니다. 게시물 수는 태그 옆 괄호 안에 표시되고, V4.5 대비 증감은 그 위에 마우스를 올리면 나옵니다.
- **없어진 태그 안내** — `skirt_hold` 처럼 지금은 사라진 태그를 검색하면 안내와 대체 태그 후보를 보여줍니다.

375px 모바일부터 넓은 PC 모니터까지 대응합니다. 넓은 화면에서는 좌측에 검색·분류 조작부가 고정되고, 관련 태그를 펼치면 우측에 따로 열려 목록이 밀리지 않습니다.

## 콘텐츠 기준

미성년자를 성적으로 다루는 태그·작품·작가 **34개를 목록과 관련 태그 양쪽에서 제외**했습니다. 이건 성인 태그 토글과 무관하게 **항상 적용**됩니다. `lolita_fashion` `gothic_lolita` 같은 패션 계열과 `child` `aged_down` `toddler` 등 연령 표현 태그는 그대로 두었습니다.

성인 태그 토글이 숨기는 대상은 **1,342개**입니다. 세부 분류의 '성인' 그룹 전체(1,244개)에, 다른 그룹에 섞여 있지만 이름만으로 명백한 것(98개, 예: `spread_legs` `no_bra` `underboob`)을 더했습니다. 관련 태그 이름 사전에서는 1,692개가 대상입니다.

이 사이트는 태그 자료만 제공하며 이미지를 포함하지 않습니다. 위키 링크는 성인 콘텐츠가 포함된 단부루로 연결됩니다.

## 파일 구조

```
index.html                  앱 전체 (코드만, 약 100KB)
debug.html                  스크롤 진단용 (index.html + 계측 오버레이)
data/tags.json.gz           태그 45,420개 — 이름·한글명·분류·게시물 수·설명·세부 분류   3.60 MB
data/related.json.gz        관련 태그 1단계 — 18,297개 태그 × 코사인 상위 60개        5.28 MB
data/related2_00.json.gz    관련 태그 2단계 — 61~200위 (앞쪽 9,148개 태그)           4.78 MB
data/related2_01.json.gz    관련 태그 2단계 — 61~200위 (뒤쪽 9,147개 태그)           4.72 MB
.nojekyll                   깃허브 페이지가 파일을 그대로 서빙하도록
README.md
```

관련 태그는 **두 단계로 나눠 받습니다.** 먼저 1단계(코사인 상위 60개)를 받아 바로 쓸 수 있게 하고, 61~200위는 뒤에서 이어 받아 준비되는 대로 패널에 채웁니다. 2단계를 못 받아도 상위 60개만으로 정상 동작합니다. 파일은 각각 9MB 이하로 나눠 두었습니다.

`index.html`은 `data/`를 **상대 경로**로 읽습니다. 그래서 루트(`https://booru-v5.github.io/`)에 올리든 저장소 하위 경로(`https://아이디.github.io/저장소이름/`)에 올리든 그대로 동작합니다. 코드 어디에도 저장소 이름이나 도메인이 박혀 있지 않습니다.

`debug.html` 은 같은 앱에 스크롤 진단 오버레이만 얹은 페이지입니다. 평소에는 쓸 일이 없습니다.

데이터는 gzip으로 압축돼 있고 브라우저의 `DecompressionStream`으로 풉니다. **Chrome/Edge 80+, Firefox 113+, Safari 16.4+** 에서 열리고, 그보다 오래된 브라우저에서는 안내 문구가 뜹니다.

## 깃허브 페이지에 올리기

1. 저장소를 만들고 이 폴더의 파일을 **구조 그대로** 올립니다 (`data/` 폴더 유지).
2. 저장소 **Settings → Pages → Source** 를 `Deploy from a branch`, 브랜치는 `main`, 폴더는 `/ (root)` 로 지정합니다.
3. 1~2분 뒤 `https://아이디.github.io/저장소이름/` 에서 열립니다. 저장소 이름을 `아이디.github.io` 로 하면 루트 주소가 됩니다.

`.nojekyll` 파일이 있어야 합니다. 없으면 깃허브가 일부 파일을 걸러낼 수 있습니다.

## 로컬에서 열어 보기

`index.html`을 파일로 직접 열면(`file://`) 브라우저가 `data/` 읽기를 막습니다. 이 폴더에서 아래를 실행한 뒤 `http://localhost:8000` 으로 여세요.

```
python -m http.server
```

인터넷 없이 쓰실 거면 단일 파일 버전(`nai_v5_tag_reference.html`)을 쓰시면 됩니다. 데이터가 파일 안에 들어 있어 더블클릭만으로 열립니다.

## 데이터 갱신하기

1. `collect_cosine.py` 로 관련 태그를 다시 수집합니다 (VPN 필요, 전체 약 1시간).
   ```
   python collect_cosine.py            # 기본: 초당 5회, 태그당 200개
   python collect_cosine.py --rps 3    # 더 천천히
   ```
   끝나면 `related_tags_merged.jsonl.gz` 가 만들어집니다.
2. 태그 마스터 데이터(`nai_v5_danbooru_tags_v5.xlsx`)를 새 스냅샷으로 갱신합니다.
3. 빌드 스크립트로 `data/` 안의 파일들을 다시 만들어 이 폴더에 덮어씁니다. (`CAP_FULL` 환경변수로 태그당 개수를 조절할 수 있고, 조각은 9MB를 넘지 않게 자동으로 나뉩니다)
4. 저장소에 올리면 끝입니다.

단부루 API는 읽기 요청이 **초당 10회**가 상한이고, 문서는 오래 도는 작업이라면 초당 1회 정도를 권합니다. 수집기 기본값은 초당 5회이고 429 응답을 받으면 스스로 느려집니다. 남의 서버이니 급하지 않으면 `--rps 3` 정도를 써 주세요.
